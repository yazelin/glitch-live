# glitch-live

《格莉奇與黑洞先生・調查篇》裡，背包那支手機的「直播」分頁長什麼樣子。

這是**畫面原型**，不是 Larch 卡片。目的只有一個：在動 Larch 之前，先把手機直播的樣子做出來看過。
確認之後才把這一份的介面搬進 [glitch-vn](https://github.com/yazelin/glitch-vn) 的 `larch/cards/phone.html`。

看這裡 → <https://yazelin.github.io/glitch-live/>

## 畫面在做什麼

1. 開場是假載入：連線中、取得串流網址、緩衝、進聊天室，約 2.4 秒。這段只有模糊的預覽圖與標題列。
2. 載完換成 `LIVE`，影片開始循環播放，聊天室一行一行滾、人數往上跳、愛心往上飄。
3. 三晚可切換（第二、五、八天），內容照 `glitch-vn/design/調查篇-直播.md`：
   第二天人數從六百跳到七百、第五天她在唸 ID、第八天聊天室在傳金魚腦合輯。
   被她唸到的那幾則是薄荷色的。

**影片本身一幀都沒有動。** 右下角那個 Gemini 浮水印是靠底部的聊天室與輸入列蓋掉的。

## 浮水印怎麼確定真的蓋住了

`assets/live-loop.mp4` 是 Gemini 生的，右下角有星形浮水印，量到的位置是影片正規化座標
`x 0.78–0.90、y 0.86–0.95`，峰值比周圍的地板亮 28 階。半透明的遮罩只會把它壓暗、壓不掉，
所以底部那塊遮罩到螢幕 84% 就是實心的，浮水印整個埋在下面。

驗法兩層，`node verify.mjs` 會跑：

| 測什麼 | 怎麼測 | 過的條件 |
|---|---|---|
| 命中測試 | 浮水印範圍取 5×5 點，每點 `elementFromPoint` | 一點都不能打到影片 |
| 像素測試 | 同一塊截兩張，第二張把影片 `filter:invert(1)` | 兩張要完全一樣 |
| 負控制 | 什麼都不改，同一塊重截一次 | 量這台機器自己的算繪雜訊 |
| 正控制 | 同一招量畫面中央（沒有介面蓋著） | 差必須很大，量不到代表測試壞了 |

為什麼用反相：把影片藏起來會換掉合成層，圓角的抗鋸齒跟著變，量到的 4/255 其實是算繪差異。
第一版就是這樣誤判的，加了負控制才看出來。

瀏覽器裡也能自己看：網址加 `?wm=1` 會把浮水印的範圍畫成紅框，
右邊主控台的「驗浮水印」按鈕跑的是同一支命中測試。

```
npm i                      # 只為了 playwright
node verify.mjs            # 跑驗收，截圖存到 shots/
node verify.mjs --headed   # 開視窗看
```

## 檔案

```
index.html                 整份原型（介面、三晚的內容、假載入、浮水印檢查都在裡面）
assets/live-loop.mp4       直播畫面，720×1280、10 秒、首尾同幀可以無縫循環
assets/poster.webp         載入時的預覽圖，也是頭像的來源
ref/                       設計參考圖
verify.mjs                 驗收腳本
```

## 搬進 Larch 之前要處理的

- `index.html` 的主控台（右邊那一塊）是原型用的，不進遊戲。
- 遊戲裡的天數要讀 Larch 變數 `day`，不是按鈕切換。
- 影片放哪裡還沒決定：Larch 的素材庫，還是外部網址。
- 自動播放：`muted` 才播得動，所以預設靜音，聲音要玩家自己開。插件卡的沙箱限制見
  `glitch-vn` 的 larch-vn skill。
